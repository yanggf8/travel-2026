## Plan-map split

`<plan-id>/plan.png` shows itinerary places with hotel and airport endpoints excluded from its bounds; `<plan-id>/plan-logistics.png` contains those hotel/airport endpoints. Per-day maps remain full route diagrams. **DOMESTIC (Taiwan) plans have NO airport segment, so there is no plan-logistics map at all** — snapshot-maps merges the booked stay's pin into plan.png (the stay is a real itinerary place for a self-drive trip) and records plan-logistics.png as skipped; the worker renders the logistics slot only when flights exist (a domestic page otherwise showed a 地圖尚未產生 placeholder wasting space). When flights DO exist (Japan), the worker renders the logistics map as a compact inset (`map-frame--inset`, ~360px 崁入小圖), not a second full-size map. The snapshot renderer composites an ArcGIS static basemap (Overpass road web as fallback) under stored OSM-derived coordinates and road geometry; it does not load OSM raster tiles.


**Day-trip inset (2026-10-01).** A far-off excursion day flagged with `set-day-excursion <day> on` (e.g. a 天橋立・伊根 coach tour 100 km from Kyoto) is kept OFF `plan.png` — its stops would flatten the city's zoom — and drawn as `<plan-id>/plan-excursion.png`. The worker renders it in a `.map-insets` row BESIDE the hotel/airport inset — two insets split the full width half-and-half (day trip first; a stack on a phone), a lone inset keeps the compact 360px right-aligned frame, and only when the PNG exists — no placeholder. Unflagging a day and re-running `snapshot-maps` deletes the stale R2 object. The day's own `day-N.png` is unchanged.
Note: the CLI's `crate::checks` module (shift-left audit) holds shared lint predicates (`check_stop_linkable`, `stop_link_problem`, …) used by BOTH the read-only lints AND write-time guards in `set-route-segment`/`set-tod` — so a stop that won't form a valid Maps link is rejected at write time, not just flagged later. (The former `../travel-2026-dashboard-rs` worktree was removed once the branch merged; all dashboard-rs work is on `master` now.)

## Behavior
- **SSR, one small inline script** — the page is fully server-rendered and works with JS off. The plan page (viewer and owner) carries ONE inline ES5 script (`render/mod.rs` `BLOCK_MEMORY_SCRIPT`, end of `<body>`, no external source) with five jobs: remembered collapse state, the 目錄 search, re-marking 現在・接下來 every minute, the offline save (SW register + SAVE + status line) and the offline banner / stale-day handling (below, 離線); logged-in owner plan pages additionally include the inline **Copy share link** (clipboard) script. (The `-rs` worker has no edit mode; the retired legacy TS edit mode is in [`docs/history/dashboard.md`](../history/dashboard.md).)
- **Page order (2026-11-12, mid-trip phone use)** — 目錄 (+ search) → 現在・接下來 `#sec-now` (during the trip only) → 常用資訊 `#sec-quick` → pending-booking alerts → the day cards `#day-N` → reference group: plan overview map + insets, companion options, 預訂總表 `#sec-summary`, 票券與憑證 `#sec-docs`, 天氣總覽 `#sec-weather` (+ 要帶的衣物), 用餐總覽 `#sec-meals`, meal alerts, transit cheat-sheet. Block ids / `data-block` keys are unchanged, so remembered collapse state survives the reorder.
- **"Now" and the trip window** — the worker takes "now" in the destination's timezone (`destination_config.timezone`, IANA, via `Intl` in `tzfmt.rs` `now_clock_in_tz`; an empty or rejected zone means no clock: no now card, every block open — never a JST fallback). `?at=YYYY-MM-DDTHH:MM` (destination local time, strictly validated; anything else is ignored) pins the clock for tests and `verify-site`; the plan page is `private, no-store`, so a pinned render is never cached. "During the trip" = the destination-local date equals a MAIN day's `date` (variants never anchor it). Outside the trip nothing changes: no now card, every block open.
- **現在・接下來 / Now & next** (`section.now-card#sec-now`, a `details[data-block]`, first in the TOC) — today's main day as a vertical timeline: each non-empty session is a native `details.now-box` (SSR, no script; served `open` only for the 現在 and 接下來 items) whose `summary` is the session name, `timesofday.time_range_start–end`, badge and focus line (activities when there is no focus); unfolded it shows the session's `transit_notes` (`div.now-transit` 🚃, same text as the day card), its TIMED route legs (`day_route_segments.start_time`; after the legs come the activities, EVERY meal rendered like the day card (main linked to its map pin, backup) and a 「看當天詳細 →」 link to the session's day-card anchor `#day-N-<morning|noon|afternoon|evening>`; a leg sits in the session whose window holds its time, else the next session — untimed legs cannot be placed, there is no session key on `day_route_segments`, so they show only in the card's collapsed 今日完整路線 list), and today's documents (same voucher links as the day card). A session with no times takes the previous session's end → the next explicit start (end of day when none), so a timeless flight 「中午」 or departure-evening still gets a window. Server-side marking: the current session (latest-starting window holding now) gets 「現在」, the first session starting after now 「接下來」, the first timed leg at/after now 「接下來」, ended sessions dim; after the last session, tomorrow's first session shows as 「明天」 (none on the last day). A day with variants links to each variant (`#variant-N`, the `details.day-variant` id; following it opens the variant and its day card). The card carries `data-now-date` / `data-now-min` / `data-start` / `data-end` / `data-at` (destination-local minutes, zone in `data-now-tz`); the script re-marks every minute and on tab focus via `Intl` in that zone while the date matches and the clock is not pinned (`data-now-pinned`).
- **常用資訊 / Quick info** (`section.quick-info#sec-quick`, always shown when data exists) — 去程 / 回程 per `flight_legs` row (「MM027 11/16（一） 15:25 KIX T2 → 17:55 TPE T1」: airport name when `departure_airport`/`arrival_airport` is stored, else the code; terminal only when stored — `set-flight --dep-terminal/--arr-terminal`), then the booked hotel: name, address, phone (`tel:` link of its digits), and stay (「11/12（四）入住 · 4 晚 · 11/16（一）退房」, nights / check-out from the plan's end date when it is after `check_in`). Address / phone carry the caption 「填入境卡／海關申報用」. Address and phone are `hotels.address` / `hotels.phone`, written by `travel set-hotel --address/--phone`. Rows without data are omitted; no rows → no card. The worker reads `SELECT * FROM hotels`, so a deploy before `travel db migrate` adds the two columns still renders (just without those rows).
- **目錄 (TOC) + search + collapsible blocks** — `nav.page-toc#toc` is the first block of the page: plain `#fragment` links (no JS needed) to each block that rendered, in page order — 現在・接下來 `#sec-now`, 常用資訊 `#sec-quick`, each main day card `#day-N` (date + theme chip, today's marked 今天 during the trip; day variants have no entry), 預訂總表 `#sec-summary`, 票券與憑證 `#sec-docs`, 天氣總覽 `#sec-weather`, 用餐總覽 `#sec-meals`. A floating 「↑ 目錄」 link (`a.toc-fab`, pure CSS `position:fixed`) jumps back from anywhere. **Search**: `div.toc-search` (an `input[type=search]`, a clear button and `ol.search-results`) is served `hidden` and un-hidden by the script (no dead box without JS; hidden in print). Typing (≥1 CJK char or ≥2 other chars, debounced) lists up to 30 matching `[data-search-unit]` elements — day-card sessions and route legs, quick-info rows, booking-summary rows, document items, weather and meal overview rows — each with its `data-search-label` (「11/15（日）· 中午」, 「常用資訊 · 回程」, 「用餐總覽 · 11/15（日）· 晴天行程 · 中午」) and a snippet with the match in `<mark>` (nodes built with textContent, never innerHTML). Case-insensitive; full-width ASCII folds to half-width. Tapping a result opens every ancestor `<details>`, scrolls to the element and flashes it; Escape or 清除 resets. The now card is never a search unit (its content repeats today's day card). Every info block is a native `<details data-block="<id>">` with its `<h2>` in the `<summary>` (the outer `section.now-card` / `section.quick-info` / `section.booking-summary` / `section.plan-documents` / `section.day[data-day]` keep their classes; the desktop day grid lives on `.day-body`); `details.day-variant` stays served collapsed. Every block is served `open`, except during the trip: today's day card is served `data-today open` and every other day card without `open`. The script restores/saves each block's (and each variant's) open state per plan in `localStorage` `trip-blocks:<plan_id>` (`key=1|0;…`, every access in try/catch) — today's card (`data-today`) always opens on load, other days get the reader's remembered state — un-hides the TOC's 全部收合 / 全部展開 buttons (served `hidden`; collapse-all closes every block incl. variants, expand-all opens every block and leaves variants as they are), opens a collapsed target when an in-page link is followed or on Back/Forward (`hashchange`), and opens every block for printing (`beforeprint`, restored on `afterprint`, not saved). A variant is keyed by its own `data-variant-day`. `travel verify-site` fetches the page with `?at=` pinned to noon the day before the plan's first main day (outside the trip, deterministic) and checks the TOC (layer `toc`: exactly one nav, every link resolves to an id, no duplicate ids, every day card listed, back link present, search input present and served hidden, every block served open — on a page that does carry a now card, day cards other than the one `data-today` card may be collapsed) and layer `quick` (no now card under the pin; the 常用資訊 card present when the plan has flights); the overview map is the first non-inset map outside the day cards; `--render` loads the same pinned URL, sets `<html data-no-block-memory>` (stops saving) and opens every `details` before measuring; its shots include `section.now-card` / `section.quick-info`.
- **Inline script items 4–5 (offline, 2026-11-17)** — (4) feature-detects and registers the same-origin `/sw.js` (the one approved exception to "no external scripts"; the page still carries ONE inline script). On every ONLINE, UNPINNED open (`<body data-served="net">`, no `?at=`) it reveals the hidden `#offline-status` and walks `data-state` `saving` → `saved` | `partial` | `kept` | `failed` (`unsupported` when there is no service worker or `register()` rejects — feature-detected, never UA-sniffed), calls `navigator.storage.persist()` when present, then after `serviceWorker.ready` sends `{type:'SAVE', url: location.href}` over a `MessageChannel` and fills 「已存好，可離線查看（地圖 n、票券 n）」 / 「已存，但 k 項未存」 + the failed items (textContent only) + a 重試 button that re-sends SAVE. The wait for the SW's reply is bounded at 60 s (`TD_SAVE_TIMEOUT_MS`) and starts BEFORE `register()`: a registration or reply that never comes ends in `failed` + retry, never parked at `saving`; each attempt carries an id so a late older reply never overwrites a newer state. A cache-served page (`data-served="cache"` / `"cache-relogin"`) sends nothing and only reveals `#offline-banner` (「離線副本 · {time} 儲存，可能不是最新」 / 「需要重新登入才能更新」), `{time}` from `data-rendered-at` formatted in `data-tz` via `Intl` (no `data-tz` → the time-less text, never a guessed zone). (5) "Today" is taken from the body's `data-tz` (else the now card's `data-now-tz`; neither → nothing is touched) via `Intl` `formatToParts`, so a copy saved yesterday and opened offline today is corrected: a stale `#sec-now` (its `data-now-date` before today, unpinned) is hidden, and today's day card (`section[data-date]`) gets every today marker (`data-today`, TOC `is-today` + `.toc-today` label) and is opened — exactly one `[data-today]` remains. This does not depend on a now card existing (trip day 1 opened offline after a pre-trip save has none). When the per-minute re-marking crosses destination midnight the whole handling re-runs.
- **Mobile-first** — phone-optimized day cards with weather (including feels-like temperature), transit, meals
- **Per-session weather** — under each main day card's weather strip, `div.weather-sessions` (`render::day::session_weather_line`): 「上午 小雨 2mm／中午 中雨 9mm（最大 5mm/h）／下午 小雨 6mm／晚上 陰」. Rows = `day_weather_sessions` (written by `fetch-weather` from Open-Meteo hourly data; the daily code is the day's WORST hour, so a steady drizzle day used to read 「大雨」). Wording from `i18n::wmo_weather` (+ session names, `wxSessMm`/`wxSessMax`); rain mm only when > 0, peak mm/h only when >= 1; a day without rows (or an unmapped code) renders nothing extra. The 現在・接下來 card shows the matching session's brief (`div.now-wx`). SSR only, no JS.
- **Weather attribution** — under each main day card's weather (after the per-session line), `div.weather-attribution` (`render::day::weather_attribution_line`): 「天氣資料：Open-Meteo（CC BY 4.0）」 / EN 「Weather data: Open-Meteo (CC BY 4.0)」, the name linked to the provider's `attribution_url` (http(s) only, else plain text; `target=_blank rel=noopener noreferrer`). Open-Meteo data is CC BY 4.0, so the credit is required. Provider name/licence/url are content in `weather_providers` (`travel set-weather-provider`), resolved per day from `days.weather_source_id` (else the first `day_weather_sessions.source`) by pipeline query [28]; only the label 天氣資料/Weather data is i18n chrome (`wxDataBy`). A day without a source id, or an id with no provider row, renders nothing extra. `travel db migrate` must create the table BEFORE a worker deploy that reads it. SSR only, no JS.
- **Weather fetch time** — the attribution line ends with 「 · 更新 11/15 08:39」 / 「 · updated 11/15 08:39」 (`wxUpdated`, `{time}`), from `days.weather_sourced_at` (UTC ISO) formatted by `tzfmt::format_in_tz` in `destination_config.timezone` via the Workers runtime `Intl.DateTimeFormat` (pipeline query [29]; omitted when tz/time missing or the runtime rejects the zone — no JST fallback; wasm-only, verify after deploy). CLI `itinerary` prints the same instant in `destination_config.timezone` ("2026-11-15 08:39 JST").
- **天氣總覽 + 要帶的衣物 (packing summary)** — `render::day::weather_overview` (`details#sec-weather`): one row per MAIN day (variants skipped) with weather, temps, feels-like, rain% and the day's 穿著建議 (the matched `clothing_tips` bands, same evaluation as the day strip). Below the table, `div.wx-pack` lists every clothing ITEM to bring with the number of main days it is needed — 「要帶的衣物 圍巾（3 天） · 雨傘（1 天）」. Items are content in `clothing_tip_items` (child rows of a band, written by `travel set-clothing-tip --item "<zh>|<en>"`); a day counts an item when one of its matched bands carries it (feels-like temps else actual, rain% as for the tips), an item counts once per day (deduped by its displayed-language text), and items list in first-appearance order (day → band group → item order). No item anywhere → no `div.wx-pack` (`validate data` INFO). The worker selects `clothing_tip_items` in its plan pipeline, so `travel db migrate` must create the table BEFORE a worker deploy that reads it — a missing table fails the plan page loudly.
- **Default ZH** — Traditional Chinese by default; `?lang=en` for English
- **ZH content** — All Chinese content stored in DB (`theme_zh`, `focus_zh`, `transit_notes_zh` scalars; ZH activities in `session_activities_zh`; meals in `session_meals`). No hardcoded content in Worker code. Content updates take effect instantly without redeploy. Use `set-day-theme --zh` for day themes, `set-tod-zh` (alias: `set-session-zh`) for session focus/transit/activities, `set-route-segment` for Chinese place names. For bulk new-destination ZH population: copy `scripts/set-kyoto-zh-sessions-v2.ts` pattern (parameterized Turso pipeline queries — required for Unicode/emoji content).
- **Anti-translate** — `lang="zh-TW"` + `<meta name="google" content="notranslate">` prevents browser auto-translation of the ZH page.
- **Multi-plan** — each plan accessed via `?plan=<slug>` (e.g., `tokyo-2026`, `kyoto-2026`). Slug derived from `active_destination` (underscores → hyphens). Root `/` shows plan index page listing all plans, sorted by earliest start date DESCENDING (nearest upcoming trip first; undated plans sort last) via `date_anchors` since 2026-09-28. The index has two server-side tabs (SSR links, `?tab=upcoming` default / `?tab=past`): 計畫與進行中 (no dates, or `end_date` ≥ today UTC) and 已過 (`end_date` < today); both pills show counts, and the empty tab renders a message instead of a list.
- **Plan nav** — hidden by default for privacy (shareable links show single plan only); add `&nav=1` to show pill-style plan switcher (plan list from DB via `listPlans()`)
- **Flight links** — Flight numbers in booking summary are clickable Google search links (opens new tab)
- **Activity links** — `https://` URLs embedded in activity text are auto-linkified (`renderActivityText()`); `\n` in activity text renders as `<br>`
- **Day card accents** — colored left border by day type: blue (arrival), green (full day), amber (departure)
- **Routes**: `/` (plan index), `/?plan=<slug>` (single plan, shareable), `/?plan=<slug>&nav=1` (with plan switcher), `/?plan=<slug>&lang=en` (EN), `/?plan=<slug>&at=YYYY-MM-DDTHH:MM` (clock pinned, destination local time), `/api/plan/<id>` (raw JSON)
- **Maps links** — Per-segment Google Maps direction links (transit/walking/driving) for every stop. Route segments stored in `day_route_segments` table, landmarks in `day_landmarks` table. Transit pill text must use place names, not service names (e.g., `成田T2 → 日暮里` not `Skyliner → 日暮里`)
- **候選位置小圖 (domestic candidate minimaps)** — Each `domestic_accommodations` candidate card with `latitude`/`longitude` renders an ArcGIS static-export basemap (600×400, 2×) centered on the trip's 旅遊地 hub — the legend stop nearest the destination center `destination_config.lat/lon` (九份 stop for jiufen, 頭城 for ne-coast-2026; tie → earliest stop; neighbor counting is NOT used because adjacent lunch stops on a road trip would outvote the stay town). Only when the destination has no center does it fall back to the stop with the most neighbors within 5 km (tie → earliest): 🚩 on the hub at the image center, 📍 on the stay with the hub→stay distance spanning a THIRD of the frame (span = 3× the stay's dominant-axis offset, floored at 0.004°; was 4×/quarter line until 2026-09-28), a dashed hub→stay connector (inline SVG, no client JS), blue labeled dots for remaining on-frame stops (off-frame stops are omitted, never clamped), caption shows 距<hub> 約 N km, image links to Google Maps. The minimap renders as the FIRST CELL of the card's bottom media strip (`candidate-gallery`), not its own full-width row. Same ArcGIS static basemap as the route snapshots (never OSM raster tiles; keep `© Esri`). No stops → tight stay-centered fallback crop (no hub flag, no connector).
- **住宿候選渲染規則 (candidate rendering)** — Only RANKED candidates (`ranking` NOT NULL) render; unranked rows are 不合條件/淘汰 notes that stay in Turso but don't list. Ranking is the publish switch: zero ranked → no candidate section at all (no heading, no frame; the section has no TOC entry) — there is no show-everything fallback, so unranking every row is how the owner hides an undecided set. The sub line counts the cards actually rendered, and a criteria line under the heading states the filter (bilingual i18n chrome; the date part is derived from the plan's date anchors). The card's price note renders the rate's tax basis (`domestic_accommodations.price_basis`, written by `travel update-accommodation --price-basis incl|excl`) right after the source — 「Booking.com 房價 · 含稅 · 2026-09-04 查」/「Agoda rate · excl. tax (taxes added at checkout) · …」; NULL (未確認) and any dirty value render NOTHING (no 口徑未知 chip — `validate data` INFO/WARN tracks the gap, the card stays quiet). The worker selects `price_basis` by name, so `travel db migrate` (adds the column) must run BEFORE a worker deploy that reads it — a missing column fails the whole plan page.
- **FIT 方案 (FIT packages)** — The listed offers are DATA: `plan_fit_offers` curated with `set-fit-offer` (package offers for the plan's destination), joined to `offers`; reasons, the criteria paragraph, and the single 推薦 pick come from `plan_fit_notes` (`set-fit-note`). The worker holds NO agency/hotel/time filters or trip-specific note text. Before booking, the section shows the FIT comparison, criteria and price differences. Once P4 is `booked`, the heading reads 「已訂 FIT 方案」/「Booked FIT package」 and only the chosen pick renders with 已訂/Booked badges; comparison criteria and price differences are hidden. Other candidates remain in Turso for reference.
- **Sharing** — a viewer opens `/?plan=<slug>&token=<t>`; the worker reads `plan_share_tokens` on every request (no cache), so a minted token works at once and a deleted one stops at once. A viewer token also opens the plan's voucher PDFs. Policy: no lasting tokens until a plan is final (CLAUDE.md); `share-token` mints/lists/deactivates, `share-token clear` deletes, and `verify-site` mints its own per-run token and deletes it after its viewer-page checks (do not run two verify-site at once). Commands → `docs/reference/CLI.md`.
- **verify-site（自動驗證，完整判準見 `docs/reference/CLI.md`）** — `travel verify-site` checks, besides the maps and the viewer page: `/sw.js` once per run (200 javascript, `Cache-Control: no-cache`, the `offlineMiss` text filled for zh+en, no `{tdMiss*}` placeholder left); every local voucher/doc link's `?v=` equals the first 12 chars of its `plan_documents.sha256` (the SW's cache-first key); the **record layer** per plan — the trip-record rows (`record_status`/`record_note`, `record_summary_zh`) read once from Turso, then the viewer page re-fetched in zh/en with `?at=` pinned to noon the day after the last dated main day, where each done row must show its 實際 badge, each skipped row its 未前往 line (route legs: no line at all), each note and each session summary its text, rows matched by `data-activity-id` / `data-meal-order` / `data-seg-order` / the session anchor; and the **notes:** layer — throwaway note fixtures (minted and cleaned up in the same run) verify note-route token isolation, privacy headers and photo serving, with owner-only edit guards needing `TRAVEL_VERIFY_SITE_OWNER_COOKIE` (a one-time `__Host-td_session` value from a signed-in browser; never stored; missing → WARN and owner checks skipped). Do not run two verify-site runs at once (each run sweeps the other's verify tokens).
- **Secrets**: `TURSO_URL` + `TURSO_TOKEN` + `GOOGLE_MAPS_KEY` (optional) via `wrangler secret put` (server-side only, never sent to browser — except Maps key which is browser-visible by design; restrict via GCP Console referrer policy)
- **Self-contained** — no dependency on other repo code; own `Cargo.toml` + `wrangler.toml` (workers-rs)
- **Live URL** (canonical): `https://trip-dashboard-rs.yanggf.workers.dev/?plan=tokyo-2026` | `/?plan=kyoto-2026`. The old `trip-dashboard.yanggf.workers.dev` 301-redirects here (path+query preserved).
- **Itinerary formats**: Supports both session-based (Tokyo) and schedule-based (Kyoto) formats. See `src/skills/travel-shared/references/itinerary-formats.md`

## 離線

同源 `/sw.js`（`src/sw.js`，由 `src/sw.rs` 填入 `offlineMiss` 文案後送出；`Cache-Control: no-cache`）把計畫頁存在手機上。Yang 2026-11-17 核可；設計見 `docs/superpowers/specs/2026-11-17-offline-dashboard-design.md`。SW 是漸進增強，關 JS 或不支援的瀏覽器照常 SSR。

### 快取規則
- **攔截範圍**：只攔同源 GET 的計畫頁導航（`/?plan=`）、`/map/`、`/voucher/`。非 GET、跨來源、`/auth/*`、`/grants/*`、`/diag/*`、`/notes*`、`/n/*`、首頁 `/` 一律不碰。任何帶 `?at=` 的請求 SW 完全略過（不讀、不寫）。
- **計畫頁 network-first**：200 直接用網路；4 秒逾時或離線 → 退到快取副本（查 `td-index`，不從網址形狀推斷），把 `data-served="net"` 改寫成 `"cache"` 讓橫幅顯示。線上但伺服器回 5xx：有副本回副本，沒有副本透傳原 5xx。沒副本又離線 → `offlineMiss` 備援頁。
- **只存「計畫頁 200 ＋ `X-TD-View` ＋ body `data-view` 相符」的回應**；登入頁、403、其他頁不存。
- **存什麼**：整頁 HTML、頁面引用的 `/map/<plan>/*.png?v=<etag>`、本機 `/voucher/<key>?v=<sha256 前 12 碼>&token=…` 票券 PDF（ZH/EN 兩頁、各 token 共用的地圖以 manifest 引用計數 mark-and-sweep，沒人引用才刪）。**跨來源圖片**（ArcGIS 候選住宿小圖、候選照片）和外部 URL 票券不存，也不在「已存好」的保證內。
- **票券 `?v=` 版本鍵**：有 `v` 的 `/map/`、`/voucher/` 是 cache-first，已在快取就不重抓；沒有 `v` 的（飯店 `voucher_url` 對不到 `plan_documents.r2_key`）每次 SAVE 重抓覆蓋，讀取時 network-first（4 秒退快取）。所有本機 `/voucher/` 連結由同一個 helper 產生。
- **SAVE**（頁面送 `{type:'SAVE'}`，每次線上、無 `?at=` 的開啟都跑）：重抓原網址，驗證後逐一抓資產；**每個資產 45 秒逾時**（`ASSET_TIMEOUT_MS`，低於頁面等回覆的 60 秒；逾時算該項失敗，10 MiB PDF 在 2 Mbps 約 40 秒仍可完成）。寫入順序：資產 → manifest → HTML → `td-index`。
  - 全部成功 → 替換副本並 sweep；有失敗且已有完整副本 → 舊副本、舊 manifest 原封不動（不 sweep），回報失敗項與舊副本時間；有失敗且沒有副本 → 寫入不完整副本，列出失敗項。
  - **同網址、同儲存鍵的 SAVE 串行**（`saveTails`），一個卡住的請求不會擋住後面的存檔；**絕不改指向較舊的副本**：`data-rendered-at` 比已存副本舊的 SAVE 什麼都不寫，`td-index` 也不會被較舊的跨角色存檔搶走。
- **內容 cache 名稱固定**（`td-viewer`、`td-owner`、`td-index`，不帶 SW 版本）；SW 更新、`activate` 從不刪它們，旅途中換 SW 不會讓離線能力倒退。`install` 用 `skipWaiting()`、`activate` 用 `clients.claim()`。

### owner / viewer 隔離
- `X-TD-View: owner|viewer` 與 body `data-view` 同源判定（`render/offline.rs` `view_of`）。viewer 副本存 `td-viewer`，鍵含 token；owner 副本存 `td-owner`，鍵不含 token。`td-index` 把正規化請求網址對到 `{role, key, savedAt, renderedAt}`，所以 owner 開 token 網址離線也找得到自己的 owner 副本。
- `/auth/logout` 導航時 SW 清空 `td-owner` 與索引內的 owner 項（若同網址有 viewer 副本則索引改指回它）。
- owner session 過期（8 小時）且不帶 token：線上 403 → **保留**副本，橫幅改「需要重新登入才能更新」（`data-served="cache-relogin"`）。帶 token 的 403 → token 已撤銷 → 刪該 token 的所有 viewer HTML、manifest、索引項，再 sweep 資產（連 4 秒逾時之後才到的 403 也會清，`waitUntil`）。

### 撤銷的取捨
`share-token clear` 之後，已存在同行者手機上的副本（含票券）在對方**下次線上開啟之前仍可離線讀**；下次線上拿到 403 即整份刪除。從不再上線的裝置上，副本會一直留著——**沒有遠端抹除**。Yang 已接受以分享連結管理為控制手段（owner 副本只在 Yang 自己的手機）。

### 回退程序
不用 feature flag。`src/sw_kill.js`（`sw::KILL_SWITCH`：`install` 用 `skipWaiting()`、`activate` 刪所有名稱以 `td-` 開頭的 cache 並 `unregister()`、什麼都不攔截）：
1. 把 `router.rs` 的 `/sw.js` 改成送 `sw::KILL_SWITCH`（沿用 `sw_headers()`），build 並部署（`cd workers/trip-dashboard-rs && unset CLOUDFLARE_API_TOKEN && npx wrangler deploy`）。
2. 受影響的裝置**線上開一次**頁面（瀏覽器取回新 `/sw.js` 後執行），確認 SW 已註銷、`td-*` 已清（Chrome DevTools → Application）。
3. 把 `router.rs` 改回原樣，重新部署。回退改動不 commit。
注意：回退後離線能力隨之消失，要在出發前或有訊號時做。

### 出發前清單（零程式碼，SW 上線前後都做；SW 失效時的備援）

- [ ] 旅途中每天線上開一次（避開 iOS 7 天清除、拿到最新版）。

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Itinerary shows blank/empty | Schedule-based format not converted | Check `render` handles both formats |
| Wrong plan content | Plan not synced to Turso | Run `./bin/travel db seed plans` |
| "Plan not found" error | Plan ID mismatch (underscore vs hyphen) | URL uses `tokyo-2026`, DB uses `tokyo_2026` |
| ZH content not showing | Missing `_zh` columns in DB | Run `set-tod-zh` CLI per session, or bulk-populate via `scripts/set-kyoto-zh-sessions-v2.ts` pattern |
| ZH UPDATE silently fails (rows_affected=0) | Inline SQL with Unicode/emoji fails encoding | Use parameterized Turso queries: `args:[{type:"text",value:"..."},{type:"integer",value:"1"}]` — integer value must be a string |
| Weather missing | Weather not fetched | Run `./bin/travel fetch-weather --dest <slug>` |
| Maps embed not showing | No `GOOGLE_MAPS_KEY` secret | `wrangler secret put GOOGLE_MAPS_KEY` (restrict key to Maps Embed API + referrer in GCP Console) |
