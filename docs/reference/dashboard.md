Meal-pin `<label>｜map:<query>` links, pending-booking alerts, transit cheat-sheet, clickable flight links. ## Plan-map split

`<plan-id>/plan.png` shows itinerary places with hotel and airport endpoints excluded from its bounds; `<plan-id>/plan-logistics.png` contains those hotel/airport endpoints. Per-day maps remain full route diagrams. **DOMESTIC (Taiwan) plans have NO airport segment, so there is no plan-logistics map at all** — snapshot-maps merges the booked stay's pin into plan.png (the stay is a real itinerary place for a self-drive trip) and records plan-logistics.png as skipped; the worker renders the logistics slot only when flights exist (a domestic page otherwise showed a 地圖尚未產生 placeholder wasting space). When flights DO exist (Japan), the worker renders the logistics map as a compact inset (`map-frame--inset`, ~360px 崁入小圖), not a second full-size map. The snapshot renderer composites an ArcGIS static basemap (Overpass road web as fallback) under stored OSM-derived coordinates and road geometry; it does not load OSM raster tiles.


**Day-trip inset (2026-10-01).** A far-off excursion day flagged with `set-day-excursion <day> on` (e.g. a 天橋立・伊根 coach tour 100 km from Kyoto) is kept OFF `plan.png` — its stops would flatten the city's zoom — and drawn as `<plan-id>/plan-excursion.png`. The worker renders it in a `.map-insets` row BESIDE the hotel/airport inset — two insets split the full width half-and-half (day trip first; a stack on a phone), a lone inset keeps the compact 360px right-aligned frame, and only when the PNG exists — no placeholder. Unflagging a day and re-running `snapshot-maps` deletes the stale R2 object. The day's own `day-N.png` is unchanged.
Note: the CLI's `crate::checks` module (shift-left audit) holds shared lint predicates (`check_stop_linkable`, `stop_link_problem`, …) used by BOTH the read-only lints AND write-time guards in `set-route-segment`/`set-tod` — so a stop that won't form a valid Maps link is rejected at write time, not just flagged later. (The former `../travel-2026-dashboard-rs` worktree was removed once the branch merged; all dashboard-rs work is on `master` now.)

## Behavior
- **SSR, one small inline script** — the page is fully server-rendered and works with JS off. The plan page (viewer and owner) carries ONE inline ES5 script (`render/mod.rs` `BLOCK_MEMORY_SCRIPT`, end of `<body>`, no external source) with three jobs: remembered collapse state, the 目錄 search, and re-marking 現在・接下來 every minute; logged-in owner plan pages additionally include the inline **Copy share link** (clipboard) script. (The `-rs` worker has no edit mode; the retired legacy TS edit mode is in [`docs/history/dashboard.md`](../history/dashboard.md).)
- **Page order (2026-11-12, mid-trip phone use)** — 目錄 (+ search) → 現在・接下來 `#sec-now` (during the trip only) → 常用資訊 `#sec-quick` → pending-booking alerts → the day cards `#day-N` → reference group: plan overview map + insets, companion options, 預訂總表 `#sec-summary`, 票券與憑證 `#sec-docs`, 天氣總覽 `#sec-weather` (+ 要帶的衣物), 用餐總覽 `#sec-meals`, meal alerts, transit cheat-sheet. Block ids / `data-block` keys are unchanged, so remembered collapse state survives the reorder.
- **"Now" and the trip window** — the worker takes "now" in Japan time (UTC+9, no DST) per request (`render/now.rs` `jst_from_ms`). `?at=YYYY-MM-DDTHH:MM` (JST, strictly validated; anything else is ignored) pins the clock for tests and `verify-site`; the plan page is `private, no-store`, so a pinned render is never cached. "During the trip" = the JST date equals a MAIN day's `date` (variants never anchor it). Outside the trip nothing changes: no now card, every block open.
- **現在・接下來 / Now & next** (`section.now-card#sec-now`, a `details[data-block]`, first in the TOC) — today's main day as a vertical timeline: each non-empty session is a native `details.now-box` (SSR, no script; served `open` only for the 現在 and 接下來 items) whose `summary` is the session name, `timesofday.time_range_start–end`, badge and focus line (activities when there is no focus); unfolded it shows the session's `transit_notes` (`div.now-transit` 🚃, same text as the day card), its TIMED route legs (`day_route_segments.start_time`; after the legs come the activities, EVERY meal rendered like the day card (main linked to its map pin, backup) and a 「看當天詳細 →」 link to the session's day-card anchor `#day-N-<morning|noon|afternoon|evening>`; a leg sits in the session whose window holds its time, else the next session — untimed legs cannot be placed, there is no session key on `day_route_segments`, so they show only in the card's collapsed 今日完整路線 list), and today's documents (same voucher links as the day card). A session with no times takes the previous session's end → the next explicit start (end of day when none), so a timeless flight 「中午」 or departure-evening still gets a window. Server-side marking: the current session (latest-starting window holding now) gets 「現在」, the first session starting after now 「接下來」, the first timed leg at/after now 「接下來」, ended sessions dim; after the last session, tomorrow's first session shows as 「明天」 (none on the last day). A day with variants links to each variant (`#variant-N`, the `details.day-variant` id; following it opens the variant and its day card). The card carries `data-now-date` / `data-now-min` / `data-start` / `data-end` / `data-at` (JST minutes); the script re-marks every minute and on tab focus while the JST date matches and the clock is not pinned (`data-now-pinned`).
- **常用資訊 / Quick info** (`section.quick-info#sec-quick`, always shown when data exists) — 去程 / 回程 per `flight_legs` row (「MM027 11/16（一） 15:25 KIX T2 → 17:55 TPE T1」: airport name when `departure_airport`/`arrival_airport` is stored, else the code; terminal only when stored — `set-flight --dep-terminal/--arr-terminal`), then the booked hotel: name, address, phone (`tel:` link of its digits), and stay (「11/12（四）入住 · 4 晚 · 11/16（一）退房」, nights / check-out from the plan's end date when it is after `check_in`). Address / phone carry the caption 「填入境卡／海關申報用」. Address and phone are `hotels.address` / `hotels.phone`, written by `travel set-hotel --address/--phone`. Rows without data are omitted; no rows → no card. The worker reads `SELECT * FROM hotels`, so a deploy before `travel db migrate` adds the two columns still renders (just without those rows).
- **目錄 (TOC) + search + collapsible blocks** — `nav.page-toc#toc` is the first block of the page: plain `#fragment` links (no JS needed) to each block that rendered, in page order — 現在・接下來 `#sec-now`, 常用資訊 `#sec-quick`, each main day card `#day-N` (date + theme chip, today's marked 今天 during the trip; day variants have no entry), 預訂總表 `#sec-summary`, 票券與憑證 `#sec-docs`, 天氣總覽 `#sec-weather`, 用餐總覽 `#sec-meals`. A floating 「↑ 目錄」 link (`a.toc-fab`, pure CSS `position:fixed`) jumps back from anywhere. **Search**: `div.toc-search` (an `input[type=search]`, a clear button and `ol.search-results`) is served `hidden` and un-hidden by the script (no dead box without JS; hidden in print). Typing (≥1 CJK char or ≥2 other chars, debounced) lists up to 30 matching `[data-search-unit]` elements — day-card sessions and route legs, quick-info rows, booking-summary rows, document items, weather and meal overview rows — each with its `data-search-label` (「11/15（日）· 中午」, 「常用資訊 · 回程」, 「用餐總覽 · 11/15（日）· 晴天行程 · 中午」) and a snippet with the match in `<mark>` (nodes built with textContent, never innerHTML). Case-insensitive; full-width ASCII folds to half-width. Tapping a result opens every ancestor `<details>`, scrolls to the element and flashes it; Escape or 清除 resets. The now card is never a search unit (its content repeats today's day card). Every info block is a native `<details data-block="<id>">` with its `<h2>` in the `<summary>` (the outer `section.now-card` / `section.quick-info` / `section.booking-summary` / `section.plan-documents` / `section.day[data-day]` keep their classes; the desktop day grid lives on `.day-body`); `details.day-variant` stays served collapsed. Every block is served `open`, except during the trip: today's day card is served `data-today open` and every other day card without `open`. The script restores/saves each block's (and each variant's) open state per plan in `localStorage` `trip-blocks:<plan_id>` (`key=1|0;…`, every access in try/catch) — today's card (`data-today`) always opens on load, other days get the reader's remembered state — un-hides the TOC's 全部收合 / 全部展開 buttons (served `hidden`; collapse-all closes every block incl. variants, expand-all opens every block and leaves variants as they are), opens a collapsed target when an in-page link is followed or on Back/Forward (`hashchange`), and opens every block for printing (`beforeprint`, restored on `afterprint`, not saved). A variant is keyed by its own `data-variant-day`. `travel verify-site` fetches the page with `?at=` pinned to noon the day before the plan's first main day (outside the trip, deterministic) and checks the TOC (layer `toc`: exactly one nav, every link resolves to an id, no duplicate ids, every day card listed, back link present, search input present and served hidden, every block served open — on a page that does carry a now card, day cards other than the one `data-today` card may be collapsed) and layer `quick` (no now card under the pin; the 常用資訊 card present when the plan has flights); the overview map is the first non-inset map outside the day cards; `--render` loads the same pinned URL, sets `<html data-no-block-memory>` (stops saving) and opens every `details` before measuring; its shots include `section.now-card` / `section.quick-info`.
- **Mobile-first** — phone-optimized day cards with weather (including feels-like temperature), transit, meals
- **Per-session weather** — under each main day card's weather strip, `div.weather-sessions` (`render::day::session_weather_line`): 「上午 小雨 2mm／中午 中雨 9mm（最大 5mm/h）／下午 小雨 6mm／晚上 陰」. Rows = `day_weather_sessions` (written by `fetch-weather` from Open-Meteo hourly data; the daily code is the day's WORST hour, so a steady drizzle day used to read 「大雨」). Wording from `i18n::wmo_weather` (+ session names, `wxSessMm`/`wxSessMax`); rain mm only when > 0, peak mm/h only when >= 1; a day without rows (or an unmapped code) renders nothing extra. The 現在・接下來 card shows the matching session's brief (`div.now-wx`). SSR only, no JS.
- **天氣總覽 + 要帶的衣物 (packing summary)** — `render::day::weather_overview` (`details#sec-weather`): one row per MAIN day (variants skipped) with weather, temps, feels-like, rain% and the day's 穿著建議 (the matched `clothing_tips` bands, same evaluation as the day strip). Below the table, `div.wx-pack` lists every clothing ITEM to bring with the number of main days it is needed — 「要帶的衣物 圍巾（3 天） · 雨傘（1 天）」. Items are content in `clothing_tip_items` (child rows of a band, written by `travel set-clothing-tip --item "<zh>|<en>"`); a day counts an item when one of its matched bands carries it (feels-like temps else actual, rain% as for the tips), an item counts once per day (deduped by its displayed-language text), and items list in first-appearance order (day → band group → item order). No item anywhere → no `div.wx-pack` (`validate data` INFO). The worker selects `clothing_tip_items` in its plan pipeline, so `travel db migrate` must create the table BEFORE a worker deploy that reads it — a missing table fails the plan page loudly.
- **Default ZH** — Traditional Chinese by default; `?lang=en` for English
- **ZH content** — All Chinese content stored in DB (`theme_zh`, `focus_zh`, `transit_notes_zh` scalars; ZH activities in `session_activities_zh`; meals in `session_meals`). No hardcoded content in Worker code. Content updates take effect instantly without redeploy. Use `set-day-theme --zh` for day themes, `set-tod-zh` (alias: `set-session-zh`) for session focus/transit/activities, `set-route-segment` for Chinese place names. For bulk new-destination ZH population: copy `scripts/set-kyoto-zh-sessions-v2.ts` pattern (parameterized Turso pipeline queries — required for Unicode/emoji content).
- **Anti-translate** — `lang="zh-TW"` + `<meta name="google" content="notranslate">` prevents browser auto-translation of the ZH page.
- **Multi-plan** — each plan accessed via `?plan=<slug>` (e.g., `tokyo-2026`, `kyoto-2026`). Slug derived from `active_destination` (underscores → hyphens). Root `/` shows plan index page listing all plans, sorted by earliest start date DESCENDING (nearest upcoming trip first; undated plans sort last) via `date_anchors` since 2026-09-28. The index has two server-side tabs (SSR links, `?tab=upcoming` default / `?tab=past`): 計畫與進行中 (no dates, or `end_date` ≥ today UTC) and 已過 (`end_date` < today); both pills show counts, and the empty tab renders a message instead of a list.
- **Plan nav** — hidden by default for privacy (shareable links show single plan only); add `&nav=1` to show pill-style plan switcher (plan list from DB via `listPlans()`)
- **Flight links** — Flight numbers in booking summary are clickable Google search links (opens new tab)
- **Activity links** — `https://` URLs embedded in activity text are auto-linkified (`renderActivityText()`); `\n` in activity text renders as `<br>`
- **Day card accents** — colored left border by day type: blue (arrival), green (full day), amber (departure)
- **Routes**: `/` (plan index), `/?plan=<slug>` (single plan, shareable), `/?plan=<slug>&nav=1` (with plan switcher), `/?plan=<slug>&lang=en` (EN), `/?plan=<slug>&at=YYYY-MM-DDTHH:MM` (clock pinned, JST), `/api/plan/<id>` (raw JSON)
- **Maps links** — Per-segment Google Maps direction links (transit/walking/driving) for every stop. Route segments stored in `day_route_segments` table, landmarks in `day_landmarks` table. Transit pill text must use place names, not service names (e.g., `成田T2 → 日暮里` not `Skyliner → 日暮里`)
- **候選位置小圖 (domestic candidate minimaps)** — Each `domestic_accommodations` candidate card with `latitude`/`longitude` renders an ArcGIS static-export basemap (600×400, 2×) centered on the trip's 旅遊地 hub — the legend stop with the most neighbors within 5 km (九份老街 for jiufen): 🚩 on the hub at the image center, 📍 on the stay with the hub→stay distance spanning a THIRD of the frame (span = 3× the stay's dominant-axis offset, floored at 0.004°; was 4×/quarter line until 2026-09-28), a dashed hub→stay connector (inline SVG, no client JS), blue labeled dots for remaining on-frame stops (off-frame stops are omitted, never clamped), caption shows 距<hub> 約 N km, image links to Google Maps. The minimap renders as the FIRST CELL of the card's bottom media strip (`candidate-gallery`), not its own full-width row. Same ArcGIS static basemap as the route snapshots (never OSM raster tiles; keep `© Esri`). No stops → tight stay-centered fallback crop (no hub flag, no connector).
- **住宿候選渲染規則 (candidate rendering)** — Only RANKED candidates (`ranking` NOT NULL) render; unranked rows are 不合條件/淘汰 notes that stay in Turso but don't list (an all-unranked set is data still being entered and still shows). The sub line counts the cards actually rendered, and a criteria line under the heading states the filter (bilingual i18n chrome; the date part is derived from the plan's date anchors).
- **FIT 方案 (FIT packages)** — The listed offers are DATA: `plan_fit_offers` curated with `set-fit-offer` (package offers for the plan's destination), joined to `offers`; reasons, the criteria paragraph, and the single 推薦 pick come from `plan_fit_notes` (`set-fit-note`). The worker holds NO agency/hotel/time filters or trip-specific note text. Before booking, the section shows the FIT comparison, criteria and price differences. Once P4 is `booked`, the heading reads 「已訂 FIT 方案」/「Booked FIT package」 and only the chosen pick renders with 已訂/Booked badges; comparison criteria and price differences are hidden. Other candidates remain in Turso for reference.
- **Sharing** — a viewer opens `/?plan=<slug>&token=<t>`; the worker reads `plan_share_tokens` on every request (no cache), so a minted token works at once and a deleted one stops at once. A viewer token also opens the plan's voucher PDFs. Policy: no lasting tokens until a plan is final (CLAUDE.md); `share-token` mints/lists/deactivates, `share-token clear` deletes, and `verify-site` mints its own per-run token and deletes it after its viewer-page checks (do not run two verify-site at once). Commands → `docs/reference/CLI.md`.
- **Secrets**: `TURSO_URL` + `TURSO_TOKEN` + `GOOGLE_MAPS_KEY` (optional) via `wrangler secret put` (server-side only, never sent to browser — except Maps key which is browser-visible by design; restrict via GCP Console referrer policy)
- **Self-contained** — no dependency on other repo code; own `Cargo.toml` + `wrangler.toml` (workers-rs)
- **Live URL** (canonical): `https://trip-dashboard-rs.yanggf.workers.dev/?plan=tokyo-2026` | `/?plan=kyoto-2026`. The old `trip-dashboard.yanggf.workers.dev` 301-redirects here (path+query preserved).
- **Itinerary formats**: Supports both session-based (Tokyo) and schedule-based (Kyoto) formats. See `src/skills/travel-shared/references/itinerary-formats.md`

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Itinerary shows blank/empty | Schedule-based format not converted | Check `render` handles both formats |
| Wrong plan content | Plan not synced to Turso | Run `./bin/travel db seed plans` |
| "Plan not found" error | Plan ID mismatch (underscore vs hyphen) | URL uses `tokyo-2026`, DB uses `tokyo_2026` |
| ZH content not showing | Missing `_zh` columns in DB | Run `set-tod-zh` CLI per session, or bulk-populate via `scripts/set-kyoto-zh-sessions-v2.ts` pattern |
| ZH UPDATE silently fails (rows_affected=0) | Inline SQL with Unicode/emoji fails encoding | Use parameterized Turso queries: `args:[{type:"text",value:"..."},{type:"integer",value:"1"}]` — integer value must be a string |
| Weather missing | Weather not fetched | Run `./bin/travel fetch-weather --dest <slug>` |
| Maps embed not showing | No `GOOGLE_MAPS_KEY` secret | `wrangler secret put GOOGLE_MAPS_KEY` (restrict key to Maps Embed API + referrer in GCP Console) |

## Deploy

```bash
# The LIVE worker is trip-dashboard-rs (Rust). Deploy:
cd workers/trip-dashboard-rs && unset CLOUDFLARE_API_TOKEN && npx wrangler deploy   # runs worker-build --release

TURSO_TOKEN=$(grep '^TURSO_TOKEN=' ../../.env | cut -d= -f2-) && unset CLOUDFLARE_API_TOKEN && npx wrangler secret put TURSO_TOKEN <<< "$TURSO_TOKEN"
```
